# h3-short-drama · MiniMax H3 短剧全流程导演 (v2.3.1)

## 〇、开工第一件事（硬门）

**建一份 RUN 进度卡，模板在 `templates/run-card.md`。没建不许动手。**

三条规则：

1. **每过一门填一行**：状态 ✅ + 产出文件路径。**空着的行 = 没做，不许跳。**
2. **每门开动前，只读该门指定的 1–3 个文件**（RUN 卡里有「阶段入口必读」表）。一次灌太多会漏。
3. **阶段顺序不许调换**：`③-0 事件分解 → ③-1 拆镜 → ③-2 景别机位`。**先定景别再想这一镜演什么，就是翻车的原因。**

> 写文件是动作，记忆不是。跳步会在表里留空，一眼可见。

**十一个门**：`G0 锁 → ① 剧本 → ② 资产 → ③-0 事件分解 → ③-1 拆镜 → ③-2 景别机位 → ③·补 表演 → ④ 编译 → ⑤ 清洗机检 → ⑤.5 拆镜复核 → ⑥ 交付`

# 〇·零、写镜行之前：**一镜四问**（正向工序）

> **这一节放在所有铁律之前，因为它比铁律更根本。**
> **铁律是负面清单，永远列不完特例**（禁了 `sill`，还有 `ledge`、`sill board`；禁了"窗外"，还有"门外、楼道、电梯口"）。
> **四问是正向工序，答完自然合规。**

## 病根：一直在「翻译」，从来没有「清点」

写提示词时的动作如果是：

```
脑子里有一个中文画面 → 找一个对应的英文短语 → 写下来
```

**这叫翻译。翻译必然丢两样东西：**

| 丢的 | 例子（2026-11-12 实测） |
|---|---|
| **物理属性**：谁拿着、朝哪开、什么材质 | 想"她拉着箱子站在门口"，写成 `the suitcase standing at the sill` —— **主语丢了、sill 是窗台** |
| **空间归属**：在哪个已定义空间里的哪个位置 | 想"门外"，写成 `the stone step outside` —— **给一个不存在的空间编了材质** |

> **读者能从上下文补全，渲染器不能。渲染器只认字面。**
> **文学靠上下文，图纸必须逐项标全。**

## 四问（答不完不许动笔）

| # | 问 | 它逼出什么 |
|---|---|---|
| **1** | **这一镜画面里有几个实体？** 人 / 道具 / 家具 / 门窗，**逐个列出来** | 漏掉谁在画面里 → 漏挂参考图 |
| **2** | **每个实体在哪？** 必须落在**一个已定义的空间**里、一个明确的位置上 | **机位跑到没定义的地方**（门外、楼道） |
| **3** | **每个实体和什么连着？** 谁的手在它上面、它贴着哪面墙、门朝哪边开、它立在什么上 | **道具自己站着**、**门的方向反了**、**词义取错** |
| **4** | **这一镜哪个实体变了？** 只能有一个 | **一镜塞两件事** |

**四问答完，镜行的句子直接就有了——不需要"翻译"。**

## 四问怎么拦住那四类错（实测对照）

**段01 Shot 1**（行李箱在窗台、没人拉）：

```
① 实体：他、她、行李箱、入户门、门框
② 位置：门半开；他在门内；她在门槛外
③ 连接：她的右手在拉杆上；门的边被他右手拉着   ← 这一问逼出"谁的手在上面"
④ 变化：他把门向内拉
```
→ 不可能写出"箱子自己站着"；第②问逼你答"门槛地板"，不会写成 `sill`。

**段02 Shot 2**（门的逻辑写反）：

```
④ 变化：门这一镜是"开得更大"   ← 第④问逼你答方向
```
→ 不会写成 `draws back to a hand's width`。

**段01 Shot 3**（机位在门外石阶）：

```
② 位置：她站在门槛外 —— 但"门外"这个空间全片没有参考图
   ↑ 第②问当场撞墙，机位自动收回室内
```

**段04/08/16**（男主漏挂角色卡）：

```
① 实体：他、她、（道具…）
   ↑ 第①问列了"他"就必须回答"他的参考图是哪张"
```

## 出口判据

> **四问的答案就是镜行本身。答不出来 = 这一镜还没想清楚，不许写。**

**特别是第③问**：只要画面里有一个"独立物件卡"的道具（箱子、手机、瓶子、包、开衫），**必须答出"谁的手在它上面"或"它立在什么上面"**。

# 〇·一、官方格式（**本地就有，每次开工先读**）

> **踩过的坑（2026-11-12）**：我凭自己蒸馏的六段式写了几十段，**从没读过本机的官方文档**。读完发现 4 处关键做法是错的。

## ★ 〇·一·零、景别铁律：**少用全景 / 远景**

> **全景、远景里人物占画面比例太小，H3 渲染出来人脸必糊。** 观众看不清脸，戏就散了。
> （2026-11-12 用户明确要求）

| 景别 | 用不用 | 说明 |
|---|---|---|
| **近景 / 特写** | **主力** | 脸清楚，情绪能演 |
| **中景 / 中近** | **可以** | 上半身，脸仍可辨 |
| **全景** | **少用** | 只在**交代空间**时用，一段最多 1 个，且必须是**转身/进出**这类有走位理由的 |
| **远景** | **尽量不用** | 人物成小点，脸完全糊 |

**替代写法**：
- 想交代"这间屋多大" → 不要全景，改用**中景带环境**（人在前景，家具在一米外）
- 想交代"他走到门口" → 不要全景，改用**中景跟一段 + 脚部特写**，或直接**切到他手放在把手上**
- 想交代"两个人离多远" → 用过肩或双人中近，靠**构图关系**而不是广角交代

**出口检查**：逐段数景别，**全景/远景超过 1 个的段，必须改。**

## 六条硬规矩（官方口径）

### ① `<Picture N>` 只用于**帧锚点**，不许给每张卡都建条目

> 官方原文：`<Picture N>`: **ONLY for concrete frame anchors** (opening/key/last frame, storyboard). If an image defines style/appearance only, cite it inside a Subject and **don't create a Picture entry**.

**角色卡 / 服装卡 / 物件卡 / 空间图 —— 全是"只定义外观"，所以一条 `<Picture N> is …` 都不该有。**

写法：
```
<Subject 1> is the man in <Picture 1>, with short black hair, ...
<Subject 3> is the flat whose room layout is fixed by <Picture 3>.
<Subject 4> is the suitcase shown in <Picture 4>; it belongs to <Subject 2>.
```
**物件归属写进 Subject**（`it belongs to <Subject 2>`），靠这个防张冠李戴。

### ② `summary` 用方括号任务前缀

```
[reference generation] Use <Subject 1>, <Subject 2>, the flat layout of <Subject 3>. <一句话剧情>
```
前缀可选：`[keyframe completion]` `[reference generation]` `[video editing]` `[video continuation]` `[audio reuse]` `[audio reference]`，可 ` + ` 组合。

### ③ `retention_analysis` 每行写「出现在哪些镜 + 理由」

```
<Subject 1> (appears in [Shot 1], [Shot 2]): fully_preserved - identity, hair and clothing remain consistent.
<Subject 3> (layout reference for every shot): weak_reference - room shapes and furniture positions are followed.
```
**只写 `fully_preserved.` 是不合格的。**

### ④ 运镜必须用**官方词汇表**，不许自造

```
类型：Zoom / Push / Pan / Truck / Tilt / Pedestal / Arc / Tracking / Shake / POV / Roll
幅度：with small / large amplitude
速度：at slow / fast speed
```

```
The camera holds static.
The camera pushes in with small amplitude at slow speed.
The camera pans with small amplitude at slow speed.
```

**病根**：写 `taken from inside the living room looking toward…` 只是"机位站在哪"，**不是运镜**。**机位照写，但每镜必须另外给一句官方运镜。**

### ⑤ 空间关系写死「内 / 外」

**段01 翻车的根因**：`in the near half of the doorway` 是歧义词，H3 把两个人都放到了门外。

```
✅ <Subject 1> stands on the interior side of the threshold, one pace inside the flat.
✅ <Subject 2> stands outside beyond the threshold, on the corridor floor.
❌ in the doorway / near half of the doorway（H3 会自己选一边，往往选错）
```

### ⑥ 否定词零容忍 + 道具必须有持有者

同前，见 〇·零 第③问。

## 官方还给了什么

- **时间戳**：`[Shot 1]` 不写时间；后续镜用 `MM:SS.mmm` 标**真正的切点**，不是每句都标
- **对话 token**：`(S1)` 按发声顺序；`<d>[Language] …</d>` 逐字保留；画外音写 `in an off-screen voiceover` 并注明嘴唇闭合；跨切 `<scenetrans>`；截断 `<cutoff>`
- **每段都要有 `overall_soundscape:` 和 `non_diegetic_music:`**（没有配乐就写 `None.`）

## 但官方**不教**你怎么想

官方教「怎么用词」，**不教**「行李箱谁拿着、门朝哪开、这个词第一义是不是你要的」。

**那部分只能靠 〇·零 的四问。四问定内容，官方格式定措辞。**

# 〇·二、分镜图驱动流程（2026-11-13 实证：一条成片已验证）

> **先画出来，再让它照着画。** 不靠文字约束 H3，靠图。
> 优点：人物不分身、房间全片一致、门向/站位/服装在图上就定死了。
> 代价：多一道工序，且分镜条一次过率低（实测 2/8）。

## 分镜条怎么做

**每段一张横向 N 格分镜条，格数 = 该段镜数（4–7 格）。** 一格一镜，从左到右按镜序。

生成方式：`cnv_generate_image`（Qwen-Image 2.1 图生图），`refFiles` 传该段相关的**角色卡 + 空间图 + 道具卡**。

prompt 里写死：
```
横向 N 格分镜条，每格是一个镜头的关键帧，格子之间有细白色分隔线。
第一格是第 1 镜……依次从左到右。
人物长相必须与参考图一致；房间必须与参考图那间客厅一致。
无文字、无字幕、无格号。
```

## 参考图张数：上限 ≥11，但**画质从 5 张起崩**

| 张数 | 结果 |
|---|---|
| 3–4 | 干净 |
| **5 起** | **同一物件被复制**（箱子+包同传 → 画面里两只箱子） |
| **两张服装卡同传** | **叠穿**（浴袍底下露出家居服裤脚） |

**规矩：每张分镜条用 4–6 张，留余量。两张服装卡不要同段同传。**

## 分镜条的四个坑（实测一次过率仅 2/8）

| 坑 | 症状 | 防法 |
|---|---|---|
| **掉格** | 要 6 格只画了 5 格 | prompt 里明确写「六格」并列出每格内容；出图后**数格数**，不对就重出 |
| **≥7 格排成网格** | 想要横条，出来 2×4 宫格 | **一段不超过 6 镜**；超过就拆段 |
| **服装卡被「穿」到人身上** | 参考图里的衣服穿到了画面里的人身上 | 服装卡只在需要时传，且 prompt 写「参考图只用于布料与版型」 |
| **同段两张服装卡叠穿** | 浴袍 + 家居服套在一起 | 一段只传一张服装卡 |

## 分镜条怎么喂给 H3

分镜图**作为一个 Subject**，不建 `<Picture N> is …` 条目：

```
<Subject K> is the storyboard of this segment, whose panels fix the framing of each shot in order.
```

正文里每镜照分镜条的那一格写，并加官方运镜句。

## 一、定位与边界

**只做一件事：把短剧从文字做到能投进 MiniMax H3 的成片级提示稿与投喂包。**

- **产出平台无关**：剥壳六段式 `.txt` + 图槽表 + 清单 JSON。跑片、排队、并发是渲染端的事，不在本包内。本包也不自带推送脚本。
- **画幅**：推荐 `9:16` 竖屏；`16:9` 横屏实测同样可用。**全片一个画幅，禁 `auto`。**
- **不做**：广告片、产品片、品牌宣传、MV、游戏片头。
- **平台规格不进生成层**：红果/抖音的"单集 60-90 秒、付费卡点"只指导 ① 剧本层；生成层只认 **4-15 秒**的独立生成单元。
- **不假装有记忆**：H3 每段独立生成零记忆。跨段连续靠「全片固定图槽 + 段首空间锚点卡复述 + 镜末正向维持句 + 末镜 1 秒定格」。

## 二、H3 的七个默认行为（**所有铁律的根**）

> 27 条铁律不是 27 个独立经验，是这 7 个默认行为的补丁。
> **遇到新坑，先问「这是哪根没顾到」；归不进这 7 根，才立新律。**

| # | 它会默认这么干 | 会导致什么崩 | 对应细则 |
|---|---|---|---|
| **1** | **按词渲染，不懂意图**。它把每个词根当画面要求去执行，否定词直接丢弃 | 写"不要越轴"它就画一条轴；写"压迫感"给皱眉+阴影；写"cinematic"回落成平光 | 4 · 12 · 13 · 21 · 23 |
| **2** | **零记忆，每段从零**。它不记得上一段长什么样、光照在哪 | 段越短脸越漂；不复述锚点就换脸换光换服装 | 1 · 2 · 15 · 27 |
| **3** | **看不见＝不存在**。画面里没有的，它当没有 | 画外的敲门被安给画内人；门内/门外被清空成空镜 | 10 · 18 · 19 · 22 · 25 |
| **4** | **没有时间感**。不写起点，它自己挑一个（常常挑成空镜） | 一镜里冒出"先空后有人"；门窗提前开、道具悬浮 | 6 · 14 · 17 · 24 |
| **5** | **单载体绑定**。一个词根只能绑一个物体，绑两个就复制 | 一左一右两个分身；人物穿过门框半透明融化；低姿态+窄缝直接死锁 | 11 · 20（含 17① 18②） |
| **6** | **一镜一个单元**。给多了就平均化，每个都只做一半 | 踩砖+停+溅三件事挤一镜 → 三件都糊 | 5 · 9 · 16 · 26 |
| **7** | **只认官方句式**。自创写法不认 | 切镜词写错就不切；越轴写 `axis` 就翻车 | 3 · 7 · 8 |

**一句话记法**：**它按字面干、不记事、看不见就算没有、不记时、一个词只绑一个东西、一镜只干一件事、只认官方说法。**

## 四、模式路由

| checkpoint | 输入 | 场景 | 输出 |
|---|---|---|---|
| `H3-Base-FL2VA` | 零图 | 纯文本段（T2VA） | **三字段** |
| `H3-Base-FL2VA` | 一图 | 首帧 / 尾帧 | 指令行 + 三字段 |

## 五、铁律二十七条（按 7 根分组 · 违反即返工）

### 根 1｜按词渲染 → 只写「可见事实」

4. **词根零容忍**：分号后禁否定词、禁镜头/摄影术语、禁抽象评价、禁心理动词、禁比喻、禁声音词。
    - **★ 描述性否定一样会被渲染（2026-11-10 H13 机检拦截实证）**：不只"不要越轴"这类指令，「没人」「不动」「没说话」同样是反向指令——它丢掉否定词、只渲染词根，`no hand is on it` 会被画成**一只手正搭在把手上**（正好反了）。
    - **四条高频改写**：`no hand is on it` → `the handle stands bare and untouched`；`nothing in the frame moves` → `the door, the handle and the floor hold completely still`；`her face is not in frame` → `only her sleeve and the wheel are in frame`；`saying nothing` → `her mouth stays closed`。
    - **不要用 skipGate 绕过**：这四类全都能正面表达，绕过去等于把 bug 留进片子。
12. **情绪必须落成四区肌肉**：禁"紧张/愤怒/委屈"，一律写成眉·眼·口·颌的可见动作 + 可见计数。
    - **★ 反应三件套（2026-11-10 实证：段01 连续两镜都是 `lifts her eyes`，等于没有情绪）**：每个情绪反应必须写满三样——
      1. **视线往哪**（躲开 / 落在物件上 / 落在他手上）
      2. **一个不自主的动作**（手指收紧、喉咙动一下、肩膀抬起、呼吸变浅）
      3. **想做却停住的动作**（嘴唇张开又闭上、抬手又放下）
    - **同场不重复**：同一角色在同一场戏里，连续两次反应**不许用同一个动作**。第一次用"躲"，第二次才能用"迎"。
    - **判据**：把这一镜的反应换到另一场戏里，还成立吗？**成立 = 太通用 = 等于没写情绪。**
13. **运镜带物理刻度 + 文戏运镜收敛**：推拉必给「距离+时长+轨道」；禁升格/Hit-Stop/急速变焦/滑动变焦/摇臂/Snorricam。**「每镜必标运镜」≠「每镜都要动」**：对话段以固定机位 + 换嘴切镜为主力，15s 段最多 1-2 镜微推。
21. **三层分工：外形锁图、空间锁位、氛围靠写**：外形层只写一句「按图」；空间层只写站位与朝向（换机位时必须复述轴线与墙面）；**氛围层写到死**。判据：**参考图能覆盖的一个字别写，覆盖不了的写到死**。段首六件套（光源方向/光质/空气介质/色板/前景景深/材质高光）最少写 ①③⑤，不占镜行字数。空词 `atmospheric/moody/cinematic` 必删（H35）。**见 `atmosphere-and-light.md`**。
    - **★ 有参考图时禁写色温数值（2026-11-10 实证：`warm 3000 K` 把奶白客厅压成琥珀色）**：色温是参考图**已经在管**的东西，而且是它管得最好的一样。提示词的优先级高于图，写错一个数值就把整间屋的调子盖掉。
    - **该写**：光源的**种类与位置**（`one bright ceiling panel overhead` / `a cooler lamp beyond the door`）、**光质**（硬/软、切不切介质）、介质与前景。
    - **不该写**：`3000 K` / `4000 K` 这类数值，以及 `warm amber` / `cool blue` 这类**替图定调**的词。
    - **没有参考图的段**（T2VA 纯文生）才写色温——那时它是唯一的光源信息。
23. **绝对方位：位置只能相对「另一个物体」写**，不能相对画框写。写 `the sink on the LEFT side of the frame` 会逼模型改造空间。自检：把所有「画面左/右」删掉，每件东西还能不能定位？

### 根 2｜零记忆 → 每段都是自足的「当前状态快照」

1. **单段 4–15 秒，默认 12–15 秒**，与载荷 `duration_seconds` 一致。一场戏优先切成 12–15 秒长段，镜头切分放在段内（`[Shot 1]…[Shot 2]…`），不要一段一镜。短于 10 秒**仅限**单镜反应/插入镜/快切蒙太奇/转场镜，且写明理由——段越短，脸和光位重新抽得越多。
    - **★ 零台词段禁令（2026-11-11 EP02 实证：6 段零台词 = 72 秒 = 全片 39%）**：短剧是台词驱动的，**每一段必须满足其一**——① 至少 1 句台词；② 至少 1 个关系变化（谁对谁变了）。**两样都没有，它就不是一段，是一句"然后"。**
    - **病根**：把"剧情 beat"当成"段落"。原稿一句「他愣了一下，摇了摇头」是**一句"然后"**，被拆成「他愣住」+「戴耳机」两段，各 12 秒 —— **24 秒没人说话**。
    - **判据**：写完一段，问「这段有没有推进？」——答不上来的，删掉或并进相邻段。
    - **反例**：收拾行李、门关上、戴耳机、吹风机、趴沙发晃腿——**这些全部是"然后"，不是"一段"**。它们要么并进相邻段当一个镜，要么必须补一句台词。
2. **Ref2VA 参考素材**：图 ≤9、视频 ≤3（每段 2-15s、总 ≤15s）、音频 ≤3（**必须挂图或视频**）、总数 ≤12。**全片图槽顺序一次钉死，每段全挂不省图**。
    - **★ 换装必须出资产卡（2026-11-11 EP02 实证：睡衣没出卡，段07 还穿正装、段09 突然变睡衣）**：只要角色在一集里换了衣服（睡衣、外套、居家服），**就单独出一张换装卡**占一个图槽。只靠正文描述服装，H3 会回落到默认那张图（P2 的白衬衫）。
    - **同一件衣服跨段必须同一个槽**：段07 起就挂睡衣卡，**不许到段09 才挂**——否则前两段先长成正装，后面接不上。
    - **★ 换装卡必须「图生图」，不许文生图重造（2026-11-12 EP02 实证：睡衣卡从零生成，脸变成了另一个人）**：输入**原角色卡**，指令只写"把衣服换成 X"；并明确列出**不许变**的东西：`脸、五官、发型、身材比例、站姿、肤色、光位全部保持原样`。
    - **判据**：出完卡，把新卡的脸和原卡并排看——**不像同一个人，这张卡作废**。换装是换衣服，不是换人。
    - **★ 服装图不必用横版 16:9**：16:9 是给「大头照 + 三视图」那种合成卡用的。单纯展示一套衣服，**竖版 3:4 或 9:16** 更合适——横版里人只占中间一小块，两边全是空墙，参考价值大打折扣。**版式按内容定，不按习惯定。**
    - **★ 派生图必须从原图生成（2026-11-12 EP02 实证：3D 剖视图凭空生成，与客厅实景图是两套空间）**：俯视图 / 等轴测图 / 平面图这类"同一空间的另一种视角"，**必须拿场景实景图做图生图输入**，指令写"把这间屋转成 45° 等轴测"。凭空生成 = 造出第二间屋，两套空间互相冲突。
    - **★ 角色卡是每段必挂项，不许省（2026-11-12 实证：段04/08/16 漏挂男主卡，三段男主会变脸）**：**只要这个角色在该段出镜（哪怕只有一镜、哪怕只是特写），他的角色卡就必须挂上。**
    - **病根**：网盘式的「逐段挂槽建议」表容易**盯着道具写**（这段有开衫→挂开衫、这段有手机→挂手机），**把人忘掉**。段08 因为"手部特写为主"就只挂了她的卡和包，结果郑屿在那段说话的三镜全是纯文字生成。
    - **症状**：正文里出现 `<Subject N> is the man: <外貌描述>`（**没有 `<Picture N>` 指向**）→ 就是漏挂。这是唯一的自动可查信号。
    - **硬检查（写进 ② 出口）**：逐段扫 `<Subject N>` 的定义句，**凡以冒号+外貌描述结尾、不以 `in <Picture N>` 结尾的，一律不合格**。这条能在提交前零成本查出来，不要等成片发现变脸。
    - **★ 禁 `sill`（2026-11-12 实证：开门镜里行李箱被画到窗台上）**：`sill` 的英文首选义是**窗台**。门槛一律写 `threshold` / `threshold strip` / `the floor strip of the doorway`。**同理禁用一切"以词的第一义为准、第二义才是你要的"的词**——模型取第一义。
    - **★ 机位不许放到没有参考图的空间（2026-11-12 实证：段01 机位写到"门外石板台阶"，而全片只定义了室内）**：全屋 3D 图只定义室内，任何"门外 / 楼道 / 电梯口 / 楼下"的机位，**H3 只能自己编一个**，编出来必错。**机位一律收回有参考图的空间内**；屋外的声音可以留在 `overall_soundscape`（声音不需要参考图）。
    - **★ 挂独立物件卡的道具，正文必须写"谁的手在它上面"（2026-11-12 实证：行李箱没人拉，自己立在门口）**：物件卡是"无人无手"的单件图，照抄进画面 = 一件自己站着的东西。必须写 `<Subject 2>'s right hand closed on its handle` 这一类持有句。同理：手机要写"谁拿着/在谁手里"、瓶子要写"立在洗手台上"。
15. **空间锚点 + 每镜维持句**：段首复述同一张锚点卡（只列资产图真实存在的单数家具，禁 `wall of / rows of`，H28）；每镜末尾加正向维持句（H24）；末镜必加 1 秒定格句（H27）。
27. **参考图自带「状态默认值」**：参考图不是空间说明书，是**某一刻的样子**——它把那一帧的状态（门开/关、有人/无人、灯亮/灭、机位在哪）当默认值。**解法一（首选）：一张图一个状态**，门开、门关各出一张，按段挂；**解法二**：状态冲突时镜行里显式写相反状态（`the front door is shut, the lens is on the interior side`），并声明该图**只作空间参考**。**配套**：② 资产门必须产出**场景状态表**，没有它进不了 ③。
    - **★ 它还自带「机位默认值」（2026-11-10 段01 实证：男主背后长出走廊）**：参考图是**从走廊往屋里看**拍的，于是凡是没有声明机位的镜头，它都默认**站在走廊里拍**——男主站在门口，背后就变成了走廊而不是客厅。
    - **规矩：每一镜先声明「机位在哪个空间、朝哪边看」**，再写画面。写 `from inside the living room, looking toward the entry door`，别写 `through the doorway` / `into the room` 这类"穿越式"表述——穿越式会把机位扔到对面。
    - **推论：画面里"没写到的那一侧"会被参考图的机位填满。** 所以镜头里有人背对或侧对时，**必须写他背后是什么**（`the milk-white wall of the flat behind him`），空着就长错。
    - **★ 门的开合必须逐镜显式声明，不许靠动词暗示（2026-11-12 实证：段02 写成"把门拉回一拃宽"，于是"她请求进来→他把门关小→她跨门槛"，逻辑整个反了）**：
      - **病根**：`留一条缝`（给他让路）和 `关成一条缝`（关门）在英文里都能写成 `draw the door leaf back to a hand's width`。**动词一歧义，门的位移方向就反了，整条进门链就散。**
      - **规矩**：凡有门的镜头，**都要写一次门当前的物理状态 + 相对上一镜的位移方向**。词汇只用这几个，不许自造：
        ```
        the door leaf stands ajar                    虚掩
        the door leaf stands open at his shoulder    开到他肩宽
        the door leaf stands open to its frame       全开
        the door leaf swings wider                   开得更大
        the door leaf swings shut                    关上
        the door leaf comes inward                   向内开
        ```
      - **出口检查**：把有门的段按顺序排出来，列一张「段·镜 / 门的状态 / 相对上一镜的动作」表。**开→关→关 这种链一眼就能看出来。**
    - **★ 氛围句必须以参考图的光为基准（同日实证：奶白客厅被我写成暖黄）**：铁律 21 说"氛围靠写"，但**写之前先看图画的是什么光**。参考图是明亮中性白，提示词写 `warm 3000 K` + `warm amber interior` → 整间屋被压成琥珀色，图被一句盖掉。**顺序是：读图的光 → 用词对齐它 → 再补图给不了的介质与前景。**

### 根 3｜看不见＝不存在 → 画外的必须「声明」，开口的两端都要有痕迹

10. **画外声用官方固定公式**：`<Subject N> (Sx) says in an off-screen voiceover: <d>[Chinese] …</d> while his/her lips remain completely closed.` 整段在门外不入画者，正文只写 `the woman outside (S1)`，**绝不写 `<Subject N>` 标签**。
18. **同框人数硬锁 + 段内依托物唯一锁**：主动作/说话人 ≤2，静默第三人可入画但只能写纯静止状态（禁旁观动词 `watches him go`，H30）；同段内无显式走位时，角色依托物与方位必须全程一致（否则画出一左一右两个分身，H32）。**细节见 `§7.2`**。
19. **画外声源动作隔离锁**：门外 `knocks / knocking / pounding`、门外脚步**严禁写进画面正文**（会被绑给画面里的人，渲成他自己敲自己家的门，H31）；只写门内可见受迫结果，敲门声放 `overall_soundscape`。**细节见 `§7.3`**。
22. **多人在场：定场帧只锁位置、不锁状态，进出场逐动作写死**：在场 ≠ 入画；写 `exactly two people are in frame` 会把第三个人从整个场景删掉。三段式：在场表 → 本镜入画 → 主动作。定场帧一次锁四样（座位/服装/道具/光位）；有进出场的镜头必须写 `blocking reference ONLY … not a state reference`。**见 `§一·补`**。
    - **★ 开口镜的两端都要有痕迹（2026-11-10《病娇女教师》段01 两次实证）**：门/帘/门缝/电梯门打开那一瞬，画面里必须同时交代两头——
      - **门内（开门的人）**：半个肩膀、一只手扶在门沿、身体侧在门框边；
      - **门外（被开门的人）**：虚焦的衣角、一只鞋、行李箱轮子、投在地上的影子。
      **只写一端 = 另一端被清空**：只写门外的人 → 门内空无一人（谁开的门？）；只写门内的人 → 门外空无一物的空镜（她凭空冒出来）。判据：**一个开合动作，画面上要能看出是谁在开、开给谁看。**
25. **空间关系闭合：每个可见元素都要挂一个参照**（附着/方位/距离/朝向）。先立地标再挂人；机位顺轴或横轴二选一，**「横看 + 纵深延伸」= 矛盾**。**见 `h3-format.md §3.4.2`**。
    - **★ 两张场景图必须写死「同一空间的不同区域」（2026-11-12 EP02 段02 实证：书桌连人复制两份、左右镜像）**：同时挂客厅图（P3）和书桌图（P5）时，若只写 `<Picture 5> is the desk corner.`，H3 会把 P5 当成**另一个房间**贴进画面，**连家具带人复制一整套**。
    - **写法**：`<Picture 5> shows only the desk area of the SAME room as <Picture 3>, standing in its far corner against the same wall as the bookcase; same floor, same wall, same ceiling panel.`
    - **★ 关键家具与门必须写单数（2026-11-12 EP02 段03 实证：走廊两侧各长出一个门，她的头出现两个）**：`the room holds one desk` / `the corridor has one door at its end` / `one bathroom door`。**不写单数，它就会复制一份，然后给每一份各配一个人。**
    - **症状对照**：画面里出现两个相同的人、两套相同的家具、两扇相同的门 → 先查「是不是两张图没写关系」和「有没有写 one」。

### 根 4｜没有时间感 → 每一镜写「起点 + 终点」

6. **首镜无时间戳**；后续 `[Shot N] At 00:04.000,` 严格递增且 < 段时长。
14. **道具物理接地**：道具首现必写支撑面（`standing on the low table`），只写相对位置会悬浮（H22）。
17. **门窗开闭状态锁 + 禁穿门融化**：人绝不穿过门洞/窗洞/有框开口（`steps out through the door` → alpha 融化，H29）；未开门段全程锁 `closed/shut`；段末有开合变化时场景标 `partially_preserved` 且开门前显式写 `the door stays shut`（防抢跑、防"双扇门分裂"，H31）。**细节见 `spatial-anchor-and-hold.md §7.4`**。
24. **分拍写：每个 `[Shot]` 至少两个时间点**，首拍 `At the first frame, …` 写清谁在哪、手在干什么；允许开场没人，但**空也要写出来**。道具动作挂在身体部位（`his right hand closes on the towel`），不写 `pulls a paper towel`。**见 `h3-format.md §3.4.1`**。

### 根 5｜单载体绑定 → 一个元素只能有一个来源

11. **同性别多说话人声学反差锁**：同段 ≥2 个同性别开口者，音高/音质/语速必须反着写（一低冷慢 / 一高亮快），做不到就拆段（H26）。
20. **高危物理死锁禁区**：禁「全蹲/跪趴低姿态 + 低机位」与「薄物穿过极窄门缝的动态过程」——会卡 76% 并冻帧（H33）。改半蹲/弯腰（`bends from the waist`）+ 物品已静置的结果态。**见 `§7.5`**。

### 根 6｜一镜一个单元 → 不塞、不并列、不超量

5. **镜行分两区**：分号前写景别·机位·运镜；分号后只写人和物的可见状态与动作。
    - **★ 同段内禁重复主体（2026-11-11 EP02 段01 实证：开头是手、结尾也是手，等于没切）**：同一段里，两个镜头**不许「同一个主体 + 同一个景别 + 同一个动作」**。开头和结尾尤其不能重复——观众会以为画面卡住了。
    - **判据**：把这段的两个镜头并排看，如果看起来像同一张图，就必须换一个：换主体（手→后颈/背/物）、换景别、或换方向。
    - **容许的重复**：刻意的"回扣"（同一构图出现在片头片尾），但段内不许。
    - **★ 机位五件套，缺一不许写正文（2026-11-10 段01/02 三次实证）**：分号前必须写完 **① 景别 ② 机位在哪个空间 ③ 朝哪边看 ④ 高度/距离 ⑤ 本镜入画有谁**。
    - **⑤ 是最容易漏的**：写「他侧身让开」却没写画面里有谁 → 他是唯一入画者，**他让开之后没人接住那扇门，门就自己关上了**（段02 实证）。凡是"让位、递东西、开门、回头"这类**需要对手的动作**，画面里必须有对手，或者明确写「对方在画外/在门后/在画面右缘」。
    - 多人同框时写清**谁是主体、谁在画外**：`a two-shot with <Subject 1> inside the doorway and <Subject 2> in the corridor beyond him`。
    - 六段式正文里同样适用：`[Shot N] At 00:0X.000, the shot cuts to <景别> taken from <空间>, looking <朝向>, <高度/距离>;` 然后再写画面。
    - **人一多就必须写**：两人以上同场、对话正反打、过肩、双人全景——机位归属一含糊，人物就会站到对面的空间里去。
    - **禁"穿越式"机位**：`through the doorway` / `into the room` / `across the threshold` 会把机位扔到对面。只写 `from <空间>, looking toward <目标>`。
9. **`[Shot 1]` 必须有一个具名主体**；禁"X 与 Y 同框"并列句式；禁悬空指示代词。
16. **动作预算：一镜一个主角动作 + ≤70 词**（>75 词 WARN，>100 词 FAIL 先丢机位，H23/H25）。
26. **一镜一个状态变化（分镜第一步）**：数正文里的"了/然后/接着"，**≥2 个状态变化必须拆镜**；一镜 = 一个主谓宾。推论三条——**动作时不说台词**、**戏核那句单人固定 ≥3 秒不切**、**最伤的话不给受害者反应**。**详见 `event-decomposition.md`**。

### 根 7｜只认官方句式 → 格式照抄，不自创

3. **正文英文**；`<d>` 内保原文，必须带语言标签（`<d>[Chinese] …</d>`）。
7. **切镜只用官方绑定短语**：`the camera cuts to` / `the shot cuts to` / `the shot transitions to` / `the shot changes to` / `the shot switches to`。
8. **越轴只写正向不变式**，不写 `line`/`axis`/`frame`：`The camera stays on the same side of them throughout; she is on the left, he is on the right.`

## 六、门的硬标准：每个门必须产出「下一个门必须读」的东西

> **纸做的门不叫门。** 写在文档里的一行字，agent 一定会跳过（2026-11-11 EP02 实证：漏了剧本稿、漏了换装卡、漏了复核，一路滑到生成）。
> **判据：如果这个产物不存在，下一个门在物理上走不下去。**

| 门 | **必须产出** | **下一个门必须怎么读它** |
|---|---|---|
| **① 剧本** | **剧本稿**：台词逐行编号 `L01…`，每行带 `[删][并][提][补][留]` | **③-1 拆镜逐镜引用 L 编号**；引不出编号 = 没写剧本 |
| **①.5 改编** | **改编表**：原稿 / 改后 / 类型 / 理由 / 用户确认勾 | 用户没勾的条目不许进 ② |
| **② 资产** | **图槽表 + 换装表 + 场景状态表**（三张都要） | **④ 编译按表挂槽**；表里没有的服装/状态就编不出 |
| **③-0 事件** | **事件卡**：类型 / 状态变化数 / **信息增量数** / 用的 L 编号 / 套用模板 A–E / 预计镜数 | **③-1 只许拆事件卡里有的镜**；**信息增量 = 0 的事件直接删** |
| **③-1 拆镜** | **镜行**（进画布脚本卡）：shot / dur / size / move / desc / **line（L 编号或台词）** / sound | **④ 段表按镜行分段** |
| **③-2 站位** | **站位块表**：每块角色的**起点位置** + 走位表（几步、从哪到哪） | **④ 位置只写进 `[Shot 1]` 一次**，其余镜头靠**维持句**保持（H24） |
| **④ 编译** | **段表**：每段 = 时长 / 含哪几镜 / 挂哪几张图 / 起点位置 / **该段台词数** | ④ 出口：**每段台词数 ≥1**，否则回 ③-0 合并 |
| **⑤.5 复核** | **密度表** + **接点表** + **语义表**（每个道具/动作的来源对不对） | **⑥ 交付必须附这三张表**，没有就不算交付 |

> **③-0 之前（可选输入，不是硬门）**：若本片有明确对标，读
> `drama-case-library` 技能内的案例索引，**只取 1 条 A 档**（B 档只有结构，不给镜头）；读
> `drama-case-library` 技能内的案例索引，**只取 1 条**最相关案例的
> 「结构」「镜头语言」两节。
> **不取它的 H3 参数与格式** —— 参数一律以本技能为准（铁律 27 条优先）。
> 读完在事件卡背面写一行：参考《X》，借了___，没借___。

### 画布上的落法（不要只在本地写 md）

| 画布载体 | 承载什么 |
|---|---|
| **脚本卡**（场 → 行） | **剧本 + 拆镜 + 段表 三合一**。`场标题`写事件卡的结论（类型·变化数·增量数·模板·镜数），`场头`写 scene/light/sound，`行`= 一镜（cells 填 shot/dur/size/move/desc/line/sound） |
| **图片节点** | 资产：角色卡 / 场景卡 / 3D 轴测图 / **换装卡** |
| **音频卡** | 音色参考：连到视频节点即生效，提示词写 `<Audio N>`，最多 3 条（详见 `references/plugin-notes.md`） |
| **视频节点** | 段。**由脚本卡生成**，不许手工凭空建 |

**画布本来就自带「脚本卡 → 生成 → 拼接」链路。手工建视频节点等于绕过它，这也是 EP02 失控的原因之一。**

### ★ 禁止自造「STAGE 汇总块」（2026-11-12 实证：同一段里人物出现两个）

官方六段式**没有**"本段固定位置"这一节。`retention_analysis` 管的是**参考图保留度**（脸/发型/服装），**不是空间位置**。

**位置只在 `[Shot 1]` 里写一次**，后续镜头靠**维持句**保持（`the desk, the chair and the sofa stay in place`，铁律 15 / H24）。

> **为什么禁**：在 `detailed_description` 里另起一个"本段位置汇总"，等于**同一件事写了两遍**。
> 两遍必然打架——段03 的 STAGE 写"她已在门口"、Shot 1 写"她在行李箱旁"，于是画了两个她。
> **汇总块 = 第二份真相 = 冲突源。从格式上删掉它，就不存在"我没注意"这回事。**

**走位段怎么写**：位置变化**逐镜写**，一镜一个位置，别在开头预告终点。

```
[Shot 1] … she kneels by the suitcase …
[Shot 2] … she stands up and walks to the bathroom door …
```
**不要**在开头写「她站在门口」，再让第二镜「她走过去」。

## 七、新增规则的判据（防止铁律无限膨胀）

1. **先归 7 根**：新坑属于哪个默认行为没顾到？归得进去 → 它只是那条根下的**新细则**，不是新铁律。
2. **同一根下的细则要合并**：如果新细则和已有的说的是同一件事的两个方向（例：门内空 / 门外空），**合成一条，写成两个方向**。
3. **归不进 7 根，才立第 8 根**。立根要给出：默认行为是什么、会导致什么崩、挂哪几条细则。
4. **案例不进 SKILL.md**：`2026-11-10 实证`这类取证留在 `references/`，主文件只留一行判据。

## 九、台词层三条硬规矩（2026-11-10 补：剧本没写到的，改编必须补）

> 这三条不属于 H3 的模型特性，是**改编写作**的规矩。它们出问题，机检查不出来，只有人看不下去。

### 1. 第一次开口必须带称呼

人物**第一次说话的镜头**，台词里必须有称呼或关系信息（`许安然？` / `阿姨` / `老板`），除非刻意保密。
**没有称呼，观众不知道这两人是什么关系**——关系是靠台词叫出来的，不是靠设定表。

### 2. 认出熟人要两拍，不能一拍

看到认识的人站在门口，真实反应是**先认出、再发问**，不是直接问"什么情况"：

```
① 「许安然？」        ← 认出，惊讶：眉毛抬起来、眼睛睁大一点
② 顿一下             ← 想说的话卡住：嘴唇张开又闭上
③ 「突然跑来我家……有什么事吗？」  ← 才转成追问：这时才皱眉
```

**压成一拍就丢掉了惊讶**，人物变成面无表情地问话。
判据：**惊讶写在"瞳孔/眉毛"上，困惑写在"皱眉"上**——两个不同的肌肉区，不能混。

### 3. 段内不加配乐

短剧段是**台词驱动**，不是 MV。`non_diegetic_music` 段内一律写 `None`，情绪靠**音效**（门锁咔哒、高跟敲地板、轮子碾门槛、呼吸）和**表演**撑。
配乐只允许出现在：片头、片尾、以及全片唯一一次的大情绪节点。

## 十、段与段的接点检查

单段好看不等于连起来好看。逐对接点查四件事：

| # | 查什么 | 不合格的样子 |
|---|---|---|
| 1 | **动作是否延续** | 上一段他关门，下一段她已经在脱鞋——中间没人交代 |
| 2 | **人物是否消失** | 上一段末是物件特写，下一段开头又是物件特写 → **连续两个物件镜，人不见了** |
| 3 | **空间是否跳** | 上一段在门口，下一段突然在客厅中央，没有走位 |
| 4 | **情绪是否接得上** | 上一段她在犹豫，下一段她已经在笑 |

**硬判据：任何一段的末镜和下一段的首镜，至少要有一个"人"在场**（除非刻意空镜收尾）。

## 十一、④.5 提交前通读（**在生成之前做，不在生成之后**）

> **为什么必须在提交前**：生成一段要 2–4 分钟算力。生成后再审，发现问题只能重跑——**成本最高的位置**。
> 而分镜稿是**线性文本**，因果链在纸上是能顺着读出来的。**读稿 10 分钟，省掉重跑 50 分钟。**
> （2026-11-12 EP02 实证：17 段返工全来自"没通读"。）

### 读法：顺着读，倒着找

从第一段第一镜往下读。每遇到下面四类东西，**立刻往回找它的来源**：

| 遇到 | 往回找什么 | 找不到就是 |
|---|---|---|
| **一个道具**（瓶子/手机/耳机/车票） | 它是哪一镜**进画面**的？谁拿起来的？ | **道具凭空出现** |
| **一个结果**（他没听见/她吓一跳/门关了） | 造成它的那个**动作**在哪一镜？ | **因果断点** |
| **一句台词的前提** | 这句话成不成立，依赖前面哪一镜？ | **台词悬空** |
| **一个效果**（雾/光/影/水汽/烟） | 它的**产生者**在不在这个空间里？ | **效果错位** |
| **★ 一个道具的归属** | **它是谁的？和台词说的是同一个吗？** | **道具张冠李戴** |

### ★ 第五问最重要：来源有了，不代表来源对了

**2026-11-12 实证**：段03 她问「我可以先用**你的**沐浴露吗」，却从**自己的洗漱袋**里掏出瓶子晃了晃——**自己有还借什么？**

- 通读第一问「沐浴露哪来的」→ 答：洗漱袋 → **通过**
- 但真正的错在**归属**：借的是他的，拿的是自己的

**判据：凡是"借/拿/给/换"这类涉及归属的动作，必须核对"台词指的东西"和"画面拿的东西"是同一个。**

| 台词 | 画面应该 | 错了就是这样 |
|---|---|---|
| 「用你的沐浴露」 | 从**他浴室**洗手台上拿起那瓶 | 从**她自己包里**掏（→ 自己有，何必借） |
| 「你的手机」 | 从他手里/桌上拿 | 掏出自己的 |
| 「还你的伞」 | 那把之前借的伞 | 一把新伞 |

### ★ 第四类带来：音色卡（音频卡）在不在

台词写完不等于能出声。**每一个开口的角色，必须在画布上有一条音色卡，并连到该段视频节点。**

| 检查 | 不合格长什么样 | 后果 |
|---|---|---|
| 该说话的每个角色都有音频卡？ | 只写了 `<d>` 台词，画布上没有音频卡 | 声音随机，角色串嗓子 |
| 音频卡**连到**这个视频节点了吗？ | 卡建了但没连线 | 等于没有音色 |
| `<Audio N>` 数量 ≤ 连线数？ | 连 2 条却写 `<Audio 3>` | 越界，模型无参考 |
| 同性别多角色**各有一条**？ | 两人共用 `<Audio 1>` | 一个嗓子演两个人（H26） |
| 音频是**音频卡**而不是图片卡？ | wav 塞进图片卡 | **生成直接报错** `Could not decode image` |

> 细节（`refAudios` 怎么写、3 条上限、自动补 `voice_definitions`）见 `references/plugin-notes.md`。
### 硬判据

> **画面里出现的任何一样东西，必须能指出它是「哪一镜带进来的」。**
> **指不出来 → 断点 → 不许提交。**

### 断点清单（④.5 的产物，必须落表）

| # | 段·镜 | 什么 | 往回找的结果 | 判定 | 修法 |
|---|---|---|---|---|---|
| 1 | 06·3 | 「是你在戴耳机啊」 | 前面没有「戴上耳机」的动作 | ❌ 因果断点 | 05 开头补一镜 |
| 2 | 03·5 | 她晃手里的瓶子 | 前面没有「从洗漱袋拿出来」 | ❌ 道具无来源 | 03·1 补取袋动作 |
| 3 | 03 | `haze down the corridor` | 走廊没有水汽来源，浴室才有 | ❌ 效果错位 | 改成 `steam behind the bathroom door` |

**表填不完 = 没通读。表里有 ❌ = 不许提交。**

## 十二、分工与审查隔离（多人 / 多 agent 时必读）

> **核心：做的人不审，审的人不做。**
> **判据**：一个人既做又审，他审的是「我当时想过没有」，不是「这里有没有错」。
> **实证（2026-11-12）**：我做的三处错——零台词段、耳机断链、STAGE 与镜行打架——**我自己审了三次，一次都没审出来**。三次都是"确认自己"，不是"找错"。

### 两类工作

| 类型 | 内容 | 谁做 |
|---|---|---|
| **判断类**（定"演什么"） | 改编决策、事件类型与信息增量、每镜的可见动作、反应设计 | 编剧 / 负责人 |
| **执行类**（"做出来"） | 资产挂图、六段式转写、建节点提交、拼接、抽帧转写 | 制作组 |

### 标准分工（三角色）

| 门 | 做 | 审 |
|---|---|---|
| ① 剧本稿 | **负责人** | **编剧**（独立审） |
| ①.5 改编表 | 编剧 | 负责人 |
| ② 资产 | 制作组 | 负责人 |
| ③-0 事件卡 | 编剧 | 负责人 |
| ③-1 镜行表 | 编剧 | **负责人（生成前最后一道）** |
| ③-2 站位 | 编剧 | 负责人 |
| ④ 编译（六段式） | 制作组 | **编剧（交叉审）** |
| ④.5 通读 | 制作组 | 负责人 |
| ⑤ 生成 | 制作组 | — |
| ⑥ 拼接 | 制作组 | — |
| ⑥ 成片验收 | — | 负责人 |

**单人执行时也一样**：写完镜行表，**隔一轮再读**（换一个视角），不要写完立刻自审。

### 两条交接硬规矩

1. **交接物必须是文件，不许靠 prompt 口述。**
   下游读不到文件就干不了活。prompt 里说"注意别写否定词"没用，文件里写死判据才有用。
2. **审查人不看作者的推理过程，只看产出文件。**
   听作者汇报"我检查过了"不算——要看文件里自检项有没有逐条打勾、勾的内容对不对。

### 负责人的职责（只有两件）

1. **给判据**：把硬门槛写进下游的任务书（禁什么、必须写什么、怎么算不合格）
2. **做审查**：读文件找错，不读汇报

**负责人不碰拆镜、不碰编译、不碰生成。一旦碰了，后面的审查就失效了。**

## 十二·补、**一步工序一个子 agent**（按工序切，不按内容切）

> **一道工序 = 一个子 agent。**
> **不是"一段戏一个 agent"，也不是"五道工序压给一个人"。**

### 两种错切法

| 错法 | 后果 |
|---|---|
| **一个人连做多道工序**（编写+生成+拼接） | 上下文溢出，后半段照抄前半段；出错分不清是哪一环 |
| **一道工序按段拆给多个 agent**（20 段 = 20 个） | **每个 agent 只看自己那一段，不知道上一段怎么收的、下一段怎么起的——上下场景关系全丢**。20 段会拍成 20 个互不相干的片段 |

### 正确切法

| 工序 | agent 数 | 它需要什么上下文 |
|---|---|---|
| ① 剧本 + ①.5 改编表 | 1 | 全片 |
| ③-0 事件卡 + ③-1 镜行表 + ③-2 站位 | 1（可与①同一人，需全片） | 全片 |
| ② 资产表 + 出卡 | 1 | 全片（要数每样东西跨几段、有没有特写、有没有功能） |
| ④ 编译（全部段） | 1 | **全片**——它要保证段与段之间的接点、服装过渡、道具链 |
| ④.5 通读 | 1（或负责人） | 全片 |
| ⑤ 生成 | 1 | 全片节点表；只负责提交与轮询 |
| ⑥ 拼接 + 抽帧自查 | 1 | 全片 |

**关键：每道工序的 agent 都必须握有"全片"，但它只做"一件事"。**
**连续性靠镜行表保证——镜行表本身就是连续性文档。编译组照表转写，不自己发明接点。**

### 一道工序太长怎么办

不按段横切，按**批次串行**：

```
编译批次1（段01–10）→ 产出文件
        ↓ 编译批次2 读批次1的产出
编译批次2（段11–20）→ 产出文件
```

**后一批读前一批的落盘结果**，接点才不会断。**并行横切必断。**

### 产出缺一不算完成

- 该工序的产出文件（落盘，可审计）
- 机检结果（FAIL 必须 0）
- 产物路径与关键数字（时长/段数/台词数）

### 负责人怎么监督

- **不逐个盯**，只做：随机抽审 2–3 处、看汇总表、验成片
- **不替它改**。发现问题退回该工序重做，**一上手审查就失效**
