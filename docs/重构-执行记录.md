### 前端拆分的做法（重要）

DSH 的客户端不是 ESM：插件客户端是 `window.__ModuleLoader__.load({ id, factory })` 的 **CJS 形态**，
`require("react")` 由 DSH 注入。所以不能直接写 `import "./x.js"`。

采用方案：**源码模块化 + 构建期内联**

```
lib/client-src/styles.js     ← 主题令牌 T / 全局样式 css / useCss（801 行）
lib/client-src/_poller.txt   ← 自动更新轮询（原 client.js 头部）
lib/client-src/_head.txt     ← __ModuleLoader__.load({ id, factory: (require) => {
lib/client-src/_tail.txt     ← 工厂尾部
lib/client-main.js           ← 工厂体（3216 行，逻辑主体）
        ↓  node scripts/bundle-client.mjs
lib/client.js                ← 产物（4051 行，仍是单文件，DSH 原样加载）
```

- 校验：`node scripts/client-smoke.mjs` 在 VM 里用桩 `window/document/require` 执行产物，
  断言 `__ModuleLoader__.load` 被调用、factory 可执行、导出 `apply` / `__CanvasApp`
- 内容保真：与原文件对比，`const css = \``、`function useCss(`、`ccv-`(1081 次)、`${T.`(87 次) 等 token 计数 1:1 一致
- 回滚：`lib/client.js.bak` + git 历史

### 过程中踩到的坑（已修复，记录在案）

| 坑 | 现象 | 处理 |
|---|---|---|
| 抽块器被模板字符串干扰 | 切错函数、把 `apply()` 一起删了 | 写 `_jsblocks.py` 做 JS 去噪（字符串/注释/`${}` 插值）后再数括号；每一步都用 `boot-smoke` 验证 `apply()` 仍在 |
| 跨模块漏 import | 运行时报 `XXX is not defined`（COMPAT_CACHE / loadSettings / waitForPrompt / downloadImage…） | 端到端 + 路由冒烟立刻暴露；smoke 增加「漏 import」静态检查 |
| 迁移丢常量 | `MODELS`/`PRIMITIVE_TYPES`/`ADAPTERS_PATH`/`BACKUP_TODAY` 留在旧文件 | 写了「被引用即搬走」的脚本，并在搬移后跑 e2e |


## 关键决策（与计划一致）

1. **不重写**：只做"搬移 + 收口"，逻辑一行不改；每搬一次立刻 `node --check` + 冒烟。
2. **先统一入口，再谈分层**：`submitJob()` 与 `submitPrompt()` 两个收口点价值最高，
   今晚 7 个故障里 4 个源于"入口不唯一"。
3. **测试面显式化**：`lib/index.js` 导出 `__test()`（14 个函数），
   让 Node 脚本能直接驱动真实链路，不必重启 DSH 就能跑端到端。

export function submitJob({ ctx, config, job, runner }) {
  job.status = "queued";
