# dsh-omni-canvas 重构计划（2026-11-03 夜）

> 本文档是重构的「计划」部分。执行过程见 `重构-执行记录.md`，测试与结果见 `重构-测试与结果.md`。
> 约束：**对外 API 路径、请求/响应字段、UI 行为一律不变**；纯结构重构 + 已确认 bug 修复。

---

## 0. 为什么重构（问题清单，来自实际故障）

| # | 现象 | 根因（代码级） |
|---|---|---|
| 1 | 绑定工作流没有进度百分比 | 提交有 2 套实现：`submitPrompt`（内置）与 `runBinding.submit`（绑定）。client_id 不一致、进度登记漏做 |
| 2 | 数字人永远"排队中" | 8 个路由各自写 `JOBS.set + enqueueJob`，口播分支提前 return 漏了 `JOBS.set` |
| 3 | 默认工作流不生效 | `gen.image/gen.video` 从不读 `defaults`，写死内置模板 |
| 4 | 超分被改成 1024×1024 | 尺寸语义只有"生成用 aspect"一套，超分被同样对待 |
| 5 | 参考图永远用工作流自带样图 | refImage 有上传、无赋值 |
| 6 | 改一个字段要改三处 | UI→API 转换分散在 `uiToApi`/`expandSubgraphs`/`translateSubgraphTargets` |

共同点：**一个概念有多份实现**。重构目标就是让每个概念只有一处实现。

## 1. 架构设计

### 1.1 分层

```
lib/
  index.js                 插件入口（≤400 行）：注册路由表 + 工具表，注入 ctx
  core/
    fs.js                  项目目录、canvas 锁、readJson/writeJson、touchProject
    comfy.js               comfyFetch / uploadToComfy / ws 连接 / 下载产物
    queue.js               JOBS + QUEUE + enqueueJob + pumpQueue + job 状态机  ★唯一
    progress.js            registerProgress / handleWsMessage / progressOf  ★唯一
    log.js                 probe 日志 + ws 日志（开关控制）
  workflow/
    convert.js             uiToApi / expandSubgraphs / translateSubgraphTargets ★唯一转换
    patch.js               patchWorkflow / patchDirector
    bindings.js            绑定 CRUD、结构校验、默认实现解析
    size.js                sizeFor / widthRatio / VIDEO_ASPECT_SIZE（唯一尺寸语义）
  jobs/
    dispatch.js            submitJob：创建 job → JOBS.set → enqueue → 返回 jobId  ★唯一入口
    image.js               runImageJob / runBindingImageJob
    video.js               runVideoJob / runBindingVideoJob / talking
    upscale.js             runUpscaleJob / runVideoLatentUpscaleJob / runBindingUpscaleJob
  caps/
    registry.js            能力声明表：能力 → runner + 必填参数 + 尺寸语义  ★唯一
  api/
    routes.js              路由表（薄）
    tools.js               AI 工具定义（薄）
  client/                  前端（第二阶段）
    index.js, api.js, store.js, canvas/*, panels/*, styles/*
```

### 1.2 关键不变式（重构后必须成立的规则）

1. **唯一提交入口**：任何 ComfyUI 提交都必须经过 `core/comfy.submitPrompt()`；它内部完成
   `client_id = dsh-omni-canvas`、`registerProgress(promptId, graph)`。
2. **唯一入队入口**：任何任务都必须经过 `jobs/dispatch.submitJob()`；它内部完成
   `JOBS.set` + `enqueueJob` + 返回 `{jobId}`。
3. **唯一转换入口**：任何 UI→API 转换都必须调用 `workflow/convert.uiToApi()`；
   绑定注入（prompt/refImage/seed/count/aspect/megapixels）在转换**之后**统一由一个函数完成。
4. **唯一尺寸语义**：能力在 `caps/registry.js` 里声明 `size: "aspect" | "native"`；
   `native` 表示不注入画幅（超分、放大类）。
5. **进度单一真相**：`core/progress` 是唯一写 PROGRESS 的地方；路由 `job.progress` 只读。

### 1.3 迁移策略（不允许一次性重写）

- 每个阶段：**搬移 → `node --check` → 跑 smoke → 提交 commit**
- smoke 脚本 `scripts/smoke.mjs` 直接 import 新模块，覆盖：工作流转换、绑定注入、
  能力解析、队列状态机、进度计算（不需要 DSH 重启即可验证）
- 端到端：用脚本直接向 ComfyUI 提交由新模块生成的图，验证真实出片（图片/超分/视频/口播）

## 2. 阶段划分

| 阶段 | 内容 | 产出 | 验证 |
|---|---|---|---|
| S0 | 护栏：smoke 脚本骨架 + `npm run check` | `scripts/smoke.mjs` | 跑通 |
| S1 | 抽 `core/`（fs/comfy/queue/progress/log） | 5 个文件 | smoke + node --check |
| S2 | 抽 `workflow/`（convert/patch/bindings/size） | 4 个文件 | 转换快照对比（重构前后 API 图一致） |
| S3 | 抽 `jobs/` + `caps/registry` + `dispatch` | 5 个文件 | 单元 + 真实提交 |
| S4 | `index.js` 变薄（≈400 行），路由/工具表搬出 | index.js 瘦身 | 全量 API 手测 |
| S5 | 前端拆 `client/`（styles→panels→canvas→store） | 8~10 个文件 | 逐屏手测 |
| S6 | 文档：执行记录 + 测试结果 | 2 个 md | 自检清单 |

## 3. 验收标准（必须全部满足）

1. `lib/index.js` ≤ 500 行，`lib/client/*` 单文件 ≤ 800 行，且无循环依赖
2. `node --check` 全绿；`scripts/smoke.mjs` 全绿
3. 端到端（真实 ComfyUI）：
   - 文生图（MOSS 绑定）：出图 + 进度百分比递增
   - 4K 超分（SeedVR2 绑定）：用**指定图**放大到真实尺寸 + 新卡片 + 连线 + 原卡不变
   - 视频（内置 H3 导演台）：出片 + 进度
   - 数字人（短文案 1 段）：状态从 queued → running → done（不再卡排队）
4. 对外 API：`binding.*` / `gen.*` / `job.*` / `canvas.*` / `env.*` 字段不变
5. 文档：计划 / 执行 / 测试 三份齐备，含失败与回滚记录

## 4. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 搬移漏依赖导致宿主启动失败 | 每阶段 `node --check` + smoke；入口保留 `export *` 兼容层 |
| 转换逻辑回归（图能跑但参数错） | 用「重构前 vs 重构后」API 图做 JSON diff（同一工作流） |
| 进度回归 | 用真实 promptId 回放 ws 事件，断言百分比序列单调 |
| 前端拆坏 | 先样式、再面板、最后卡片；每步手测一次 |

回滚：每阶段一个 commit，出问题 `git revert`。
