# 绑定机制与多参考图（实测记录 2026-10-30）

## 一、绑定的本质：只记"入口位置"，不动任何文件

```
绑定阶段（一次）
  读工作流 JSON（只读，不改）
  记录：prompt/seed/尺寸/参考图/输出 分别在「哪个节点的哪个字段」
  → 写入 ~/.dsh/omni-canvas.bindings.json
  最小参数试跑 → verified=run

生成阶段（每次）
  读同一个文件（只读）
  内存里转成 API 图 → 按绑定写值 → POST /prompt
  ❌ 不生成 API 文件、不写回工作流
```

关键点：
- **不生成、不保存 API 文件**（除非你在 ComfyUI 里自己导出）；
- 工作流文件字节不变，你手动用 ComfyUI 打开还是原样；
- 工作流被改动 → 读时重算 hash 不一致 → 标记失效，不会悄悄跑错。

## 二、参数映射的三条硬规则（都是踩坑得来的）

| 规则 | 原因 |
|---|---|
| `widgets_values` 必须按**完整控件顺序**赋值（含已连线控件的位置） | 先剔除连线字段再做顺序映射会整体错位 |
| 已连线控件**只消耗位置、不写值** | 否则会把上游连线覆盖成空串 |
| 动态下拉的子输入必须用**带点全名**（`format.bit_depth`） | 短名（`bit_depth`）ComfyUI 报 `Required input is missing` |

## 三、子图（subgraph）展开

```
父节点 type = 子图 uuid
  子图输入 → 内部连线 origin_id = -10, origin_slot = i
  子图输出 → 内部连线 target_id = -20, target_slot = j
  父节点 widgets_values[i] ↔ 子图第 i 个输入
```

映射字段时要用 **`inner.inputs[link.target_slot].name`**，不能用控件列表下标
（插槽顺序含 model/positive/latent 这类 socket，和控件不是同一套）。

实测：`image_qwen_image_2_1_t2i.json`（含子图）展开后出图成功，11.7 秒。

## 四、多参考图编辑（已验证可用）

内置 `edit.json` 走 `BatchImagesNode`（节点 27）+ `TextEncodeQwenImage21.images.image_1`。

**实测**（2026-10-30）：
- 图 A：橘猫坐在木桌上
- 图 B：白瓷内壁的木制咖啡杯
- 提示词：`<image1> 里的猫放在 <image2> 的杯子里，保持两者风格`
- 结果：橘猫坐在木杯里（**两张参考图都被正确使用**）

提示词里用 `<image1>`…`<imageN>` 指认；画布上的连线数量 = 参考图数量。
